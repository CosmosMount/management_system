# 需求追踪矩阵

## 1. 使用说明

该矩阵把 v2.1 设计、用户后续决策、实现组件、数据和测试连接起来。开发 PR 应引用对应 `REQ`；QA 用同一 ID 建用例。

矩阵中的目标行不自动代表完成。状态口径为：**已实现**（当前代码和当前验证证据齐全）、**计划**（目标冻结但阶段门禁未完成）、**延期**（不进入 S0–S10）。`2499952` 中的 P5 handoff 只是 `e0317cc` 在 2026-07-29 01:00 CST 的历史快照，`345b5b0` 是后续 adapter/首批 UI，`f96ddd37` 冻结了再次关单基线；当前 S1 证据以随后的 P5-R01～R05 提交和最终回归为准。

## 10. 设计偏差记录

《项目管理系统设计 v2.1》原文定义 Project 上层容器和 Project Status。用户在后续决策中明确：

- 不保留 Project 实体。
- Project 只作为 Tag 概念。
- 旧项目管理数据已直接清理，新系统不导入旧 Project 或旧 Task。

因此本矩阵以用户后续决策为最高产品基线，REQ-001~003 覆盖并替代设计文档中的 Project 数据结构要求。其他 Task、Node、Plan Version、Work Segment、Permission、Notification 和 Audit 原则继续采用。

### 3.3 S2 已交付能力边界

- `TaskPlanVersion.plannedStartAt` 数据库可空；新建 Task/Revision 和 Draft replace 的 chronology 由服务端校验。
- Draft metadata/member/plan replace 与 Active metadata/member/tag mutation 均有 session-bound Server Action；乐观并发使用 `lockVersion`，稳定错误码不依赖消息文本。
- Draft plan replace 保留合法 nodeId，拒绝隐式删除仍被 Segment 引用的节点；Active 计划语义仍必须走 Revision。
- TimeCanvas 采用 `[start,end)`、366 天范围、显式 ID 50、行分页 25/50、5,000 time-object 和独立 conflict/anchor budget；超限明确报错而非截断。
- Full Segment 与 Busy Block 在服务端完成可见性分流；Busy DTO 不含源 Segment/Task/Node/Tag/创建人/version token。
- placement preview 与最终 mutation 复用权限、关联和冲突规则；Segment/Revision 变化后在事务内按统一锁序重扫 Conflict。
- People、Task、Tag 使用绑定过滤条件的稳定游标；Task/Plan 完整查询可读回 `relatedTaskId` 与 `plannedStartAt`，版本 diff 包含计划开始时间。

### 审查策略

- 不再为每个小修复启动多路 reviewer。
- 每个阶段由主代理完成完整 diff 自审、定向测试和阶段门禁。
- 阶段末最多调用一个独立只读 reviewer 做宽颗粒度审查；reviewer 不得运行测试、build、数据库或修改文件。
- actionable finding 由主代理修复并重跑受影响门禁；无须为同一小包重复多轮形式化审查，但已知 High/Critical 必须清零。

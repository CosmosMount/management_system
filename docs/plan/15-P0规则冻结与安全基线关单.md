## 2. 冻结决策

| 项 | 冻结结果 | 后续影响 |
|---|---|---|
| 执行对象 | 无 Project，仅 Task + Tag | P1 不创建 Project 或迁移映射 |
| 旧数据 | 不导入、不双写、不保留 legacy 标记 | 新项目管理从空数据集开始 |
| Revision 默认 | `REVIEW_REQUIRED` | P3 默认复核，例外由 Task 策略显式配置 |
| Task 可见性 | 成员 + 范围管理员 + 系统管理员 + 授权审计 | P1 必须先实现 `readableWhere` 和 deny 测试 |
| 自审 | 默认禁止提交人自审 | `allowSelfReview` 仅 System Administrator 可开且写审计 |
| 组织范围 | Task 独立保存 `team + techGroup` | Tag 不提供权限或组织继承 |
| 业务时区 | `Asia/Shanghai` | cron 业务日期、逾期 event key、UAT 日期按该时区 |
| 通知渠道 | 站内 + 飞书 | 项目管理只入队，不直接调用飞书 API |

正式 ADR：`docs/adr/2026-07-28-p0-project-management-rule-freeze.md`。

## 3. 状态机冻结摘要

- Task：`DRAFT -> ACTIVE -> COMPLETED/FAILED/CANCELLED/TIMEOUT -> ARCHIVED`；已结束 Task 不恢复。
- Plan Version：每个 Task 恰好一个 `CURRENT`；`CURRENT/HISTORICAL` 核心计划内容只读。
- Node：每个未结束 Task 最多一个 Active Milestone；Plan Version 内 Node 必须线性、连续、无分支。
- Milestone Review：`PENDING/APPROVED/REJECTED/REVISION_REQUIRED` 多次保留；只有 Approved 推进。
- Revision：必须基于仍为 Current 的版本生效；Completed 事实不可改；生效原子切换唯一 Current。
- Termination：Success/Failed/Cancelled/Timeout 均需确认；时间到期不得自动 Timeout。
- Work Segment：Planned/Actual 独立于 Task 状态；Segment 不自动完成 Milestone，也不自动调整计划。
- Resource Conflict：只检测、解释、提醒和建议；没有用户确认不得修改 Segment。

## 4. 权限与安全基线

- 所有写入口第一步认证和 Zod 校验，服务端授权不可由 UI 隐藏替代。
- 列表和详情必须用 `readableWhere` 防止 ID 枚举。
- Tag 无成员、无状态、无权限继承。
- 批量操作逐项验证归属；混入越权对象时全批失败。
- 审计 append-only，普通应用角色不得更新或删除审计。
- 附件下载按 Task/Review/Segment 可见性授权，不暴露文件系统路径。
- 自动化测试必须强制 `NOTIFICATION_DELIVERY_DISABLED=true`；项目管理 action/service 禁止直接导入 `sendFeishuDirectMessage()`。

硬门禁：

- 共享表行数或稳定 hash 意外变化。
- 出现旧 Project/Stage 表、带旧字段签名的 Task 表、带旧特征值集合的项目管理 enum、`Pm*` enum、`channel=progress` outbox 或 `PROJECT_MANAGER` 角色。
- 出现 `legacySource*`、migration map、`migrationNeedsReview` 或 legacy Tag。
- 采购、反馈、认证、附件、通知安全回归失败。
- 自动化测试产生真实飞书投递。

## 6. UAT、性能与发布成功标准

UAT 必须确认：

- 用户看到的是 Task + Tag，不存在 Project 入口或旧数据导入标记。
- Task Draft、激活、Review、Revision、Termination、Segment、Conflict 和通知主流程符合状态机。
- 权限受限用户无法枚举或操作无权 Task/Segment/审计/通知。
- 桌面 `1440x1000` 与 Pixel 5 均无错误覆盖层、未处理浏览器错误或意外横向滚动。

性能基准数据和目标沿用 `docs/plan/10-测试策略与验收用例.md`：

- 10,000 Task、100,000 Work Segment、单 Task 50 个版本/每版 100 Node、100,000 站内通知。
- Task 列表首屏 p95 < 800ms；Task 工作台首屏 p95 < 1.2s；14 天资源时间轴 p95 < 1.5s；版本比较 p95 < 1.0s；单人 90 天冲突扫描 < 2s；普通 action DB 事务 p95 < 500ms。

发布成功标准：

- 新 schema 从空库和含共享数据快照部署成功。
- Account/Person 初始化 dry-run/APPLY 幂等且冲突为零。
- 两次 schema 发布演练和一次整库/上传 volume 恢复演练通过。
- `npm run check`、`npm run build`、领域/集成/E2E、采购完整回归、通知禁发测试和安全测试通过。

# 界面信息架构与交互计划

> 状态（2026-08-01）：本文涉及资源冲突、冲突中心、投入比例、冲突通知或冲突扫描的设计已由“删除资源冲突与投入比例”决策取代，仅保留历史背景，不代表当前实现。

## 0. 状态与适用基线

本文描述前端 v1.0 **目标状态**，不表示所有页面已经实现。当前 `345b5b0` 已实现 `/progress`、Task 列表、Task 工作台、资源列表、冲突中心、通知中心和项目管理 notification channel adapter 的首批卡片/列表式接入；统一 `TimeCanvas`/`TimeAgenda`、Task Composer、个人时间线、待我处理、Tag 管理以及下述完成态均为**计划**。

若本文与旧“三步向导”、分离的“当前计划/人员投入”默认页或四块等权首页描述冲突，以 `docs/adr/2026-07-30-project-management-frontend-v1-execution-baseline.md` 和 `project-management-frontend-design-v1.0/` 为准。

## 1. 导航结构

```text
项目管理
├── 我的工作
├── 我的时间
├── 全部 Task
├── Tag 管理
├── 资源计划
├── 资源冲突
├── 待我处理
├── 站内通知
└── 管理设置（有权限时）
```

系统没有 Project 入口。默认首页以 Task 和个人时间计划为中心，Tag 只用于筛选。

## 3. 首页“我的工作”驾驶舱

目标首页不是四块等权卡片的模块目录。`345b5b0` 的四卡片布局仅是已实现接入基线，S8 必须重构为指标条、个人时间预览、统一 Action Inbox、Active Task 紧凑列表和折叠通知。

首屏回答：

- 我当前负责哪些 Active Milestone。
- 今天和未来 7 天有哪些 Planned Segment。
- 哪些 Planned Segment 等待确认。
- 哪些 Milestone 临期/逾期。
- 我有哪些待 Review / 待 Revision 审批。
- 我有哪些未读站内通知和资源冲突。

卡片必须可直达对象，不把所有操作堆在首页。空状态要说明下一步，例如“当前没有计划工作，可创建 Planned Segment”。

## 4. Task 列表

### 4.1 筛选

- 状态、优先级。
- 是否独立 Task。
- Tag。
- 我参与的角色。
- Active Milestone 负责人。
- Milestone 到期范围、是否逾期。
- 是否有待确认 Revision/Review/Conflict。
- 组织范围（team/techGroup）。
- 归档/逻辑删除历史仅有权用户可见。

筛选写入 URL，刷新可复现。大列表使用服务端分页，不一次加载全部 Node/Segment。

### 4.2 列表字段

- Task 名称与状态。
- Tag。
- 当前 Active Milestone。
- 当前里程碑预期完成时间/逾期。
- Task Owner。
- 当前计划版本号。
- 最近一次业务变更时间。
- 风险/冲突/待审批徽标。

## 5. 创建 Task：单页 Plan Composer

旧三步向导方案已被覆盖。`/progress/tasks/new` 在一个工作台内同时展示 metadata、固定 `team/techGroup`、Tag、related Task、成员多角色、Revision 策略、计划开始、Milestone/Termination 画布、Inspector 和校验问题列表，使用户调整节点时始终保留全局时间上下文。

创建规则：

- 创建成功后得到 Draft Task；用户显式激活后首个 Milestone Active。
- `plannedStartAt` 对新 Task 必填；Milestone 可同日，按 `sequence` 非递减；Termination 不得早于最后一个 Milestone。
- 每个 Task 恰好一个 active OWNER；0 或多个 OWNER、同一 Person 重复相同 role 立即报错。同一 Person 可兼任多个不同 role，权限取并集。
- `allowSelfReview` 默认关闭，只有 System Administrator 可开启且必须审计。
- 新建 Task 不创建初始 Segment；创建后在 Task 工作台排期。
- 本地草稿使用按部署环境和 `accountId` 隔离、带 `schemaVersion` 的 localStorage；失败不清草稿，成功才清理。
- Milestone 支持添加、复制、同日排序、移动和删除；Termination 固定末尾。
- 拖动同时提供键盘上移/下移和 Inspector 精确录入；服务端在最终提交时再次验证。
- Pixel 5 使用纵向节点编辑，不显示压缩的桌面甘特图。

## 6. Task 工作台

### 6.1 标签页

| 标签 | 内容 |
|---|---|
| 计划与资源（默认） | Current Plan、参与人 Planned/Actual、Busy 和 Conflict |
| 概览 | Task 元数据、成员、当前状态、当前 Milestone、快捷动作 |
| 修订与历史 | Revision、历史版本、版本比较 |
| 验收 | 当前/历史 Milestone Review |
| 审计 | 关键业务事件 |

`345b5b0` 当前把“当前计划”和“人员投入”作为纵向卡片展示，这只是已实现基线；S6 将它们合并为默认“计划与资源”视图。Draft 节点只通过 `replaceTaskDraftPlan` 编辑，metadata（含 Draft tags）和成员分别调用独立 Draft action。Active metadata、members、tags 分别调用 `updateTaskMetadata`、`replaceTaskMembers`、`replaceTaskTags`；Active/Historical 计划节点只读，语义修改必须进入 Revision，终态/Archived 不显示可提交入口。

### 6.2 当前计划时间线

视觉语义：

- Current：实线、高对比。
- Historical：弱色、虚线、默认折叠。
- Milestone：目标节点。
- Revision：橙色版本切换节点。
- Termination：明确终点样式。
- Active：主色描边和“当前”标识。
- Completed：成功标识但保留原计划时间。
- Revised：弱化并指向替代版本。

时间线不能只靠颜色表达状态，必须同时显示图标和文字。

## 7. Revision 编辑与比较

### 7.1 编辑器

进入 Revision 时固定展示：

- 修订原因。
- 基线版本号。
- 修订起始节点。
- 受影响 Milestone 数量。
- 受影响 Planned Segment 数量。

用户在候选计划中新增、删除、调整 Node。Completed 前缀锁定只读。

### 7.2 版本比较

比较视图按三层显示：

1. 结构：新增、删除、移动 Node。
2. 字段：目标、条件、时间、验收要求变化。
3. 资源：关联 Planned Segment 是否需要重新确认。

移动与“删除后新建”必须区分。每项差异显示旧值、新值和 Revision 原因。

### 7.3 并发冲突

若基线已不是 Current：

- 不自动覆盖。
- 显示“当前版本 vN，你的草稿基于 vM”。
- 提供查看新差异、复制草稿内容到新 Revision 的受控操作。
- 用户确认前不写任何 Current Plan。

## 8. Milestone Review

当前 Milestone 面板分：

- 目标/条件/截止。
- 提交证据。
- 历史 Review 时间线。
- Reviewer 操作。

Approved、Rejected、Revision Required 使用独立按钮和确认对话框。Rejected/Revision Required 的说明必填。审批前展示 Task 名称、当前版本和 Milestone，避免用户在错误上下文操作。

## 9. Work Segment 交互

### 9.1 人员时间轴

- 行：Person。
- 横轴：时间。
- Planned：空心/浅色/虚线。
- Actual：实心。
- 冲突：边缘警示和冲突徽标。
- Revised Node 关联：待确认图标。

时间轴支持：

- 7/14/30 天范围。
- 人员、Task、Tag、Role、Priority 筛选。
- 拖拽调整 Planned Segment。
- 框选后批量创建。
- 多选后批量移动/取消/确认。
- 点击打开侧边详情，不跳失当前时间范围。

交互边界：

- Actual 不能在画布中拖动；有权限时只在 Inspector 中精确修改并保留历史。
- 禁止跨人员行拖放；目标人员行必须显示 invalid drop 状态。
- 批量 mutation 由服务端事务全成全败，前端不得逐条发送无上限并发请求。
- 其他 Task 的不可见占用只能使用服务端返回的 Busy Block；前端不得取得完整 Segment 后自行遮挡。

### 9.2 计划确认

Planned 到期后，成员可：

- 一键“与计划一致”生成 Actual。
- 修改实际时间/Allocation/产出后确认。
- 部分确认并保留剩余 Planned。
- 标记未执行并填写原因。

默认表单只显示必要字段，高级字段折叠，符合低记录负担原则。

## 10. Resource Conflict

Conflict 在两个位置显示：

- 人员时间轴：发生位置标记。
- Task“计划与资源”：关联 Task 上下文标记。

冲突详情必须解释：

- 时间范围。
- 涉及 Segment。
- Allocation 总和。
- Role、Priority、Task。
- 触发规则。
- 可选建议。

操作只有“确认已知、调整 Segment、解决、忽略至某日”。建议不自动执行。

Conflict DTO 必须返回操作 capability。suggestion preview 与 resolve/apply 使用相同处理权限；普通只读用户和只看到 Busy 的用户不能取得隐藏 Segment 的 ID、时间、版本令牌或 proposal。preview 不写库，apply 必须显式确认并携带最新版本令牌。

## 11. 待我处理

`/progress/approvals` 与首页 Action Inbox 使用同一权限过滤后的待办来源，至少汇总：

- 已到期或进入 `PENDING_CONFIRMATION` 的本人 Planned Segment。
- 待处理的 Milestone Review。
- 待审批或待修正的 Revision。
- 有处理能力的 Resource Conflict。
- 待确认的 Termination。

列表按逾期程度、严重度和发生时间排序。每条待办跳转前后均重新检查对象权限；不可见对象不返回名称、标识或业务详情。Segment 必须提供完整确认、部分确认和精确表单入口，Pixel 5 不依赖画布拖动。

## 12. 站内通知

顶部铃铛显示未读数，通知中心支持：

- 未读/全部。
- 类型筛选。
- 标记已读/全部已读。
- 跳转业务对象。
- 事件级飞书偏好设置入口。

站内通知不会因为用户关闭飞书而消失。已删除或无权对象的链接显示“对象不可用”，不泄露名称或详情。

## 13. Tag 界面

- 展示 Tag 名称、颜色、说明和关联 Task 数量。
- 删除 Tag 明确提示“只移除分类，不删除 Task”。
- Task 详情可随时添加、替换或移除多个 Tag。
- 不展示 `legacy-import` 或其他旧来源标记；所有 Tag 都由新系统创建并遵循同一行为。

## 14. 响应式与无障碍

### 14.1 桌面

- 1440x1000 为主验证尺寸。
- 时间轴可横向滚动，但页面本身不得意外横向溢出。
- 大型比较视图允许固定双栏，最小列宽明确。

### 14.2 移动

- Pixel 5 作为自动化基线。
- TimeCanvas 页面改用共享 DTO 的 TimeAgenda/垂直卡片。
- 版本比较改为逐项“旧/新”堆叠。
- 资源时间轴改为按人员的日列表，不强行缩小桌面甘特图。
- 批量拖拽在移动端提供表单式日期调整。

### 14.3 无障碍

- 所有拖拽都有键盘等价操作。
- 图标有可读名称。
- 状态不只靠颜色。
- 对话框焦点锁定，关闭后返回触发控件。
- 表单错误关联字段并聚焦首个错误。
- 时间和百分比提供屏幕阅读器文本。

## 15. 本轮延期

以下能力不进入 S0–S10：Unavailable Time 模型、跨人员重新指派、保存资源视图、自动资源平衡、复杂依赖线和 Task 创建时初始 Segment。延期项不得在 UI 中显示为可用能力，也不得以绕过服务端契约的客户端逻辑实现。

## 16. 极端状态检查

每个页面必须检查：

- 超长 Task/Milestone/人员/Tag 名称。
- 200 个 Node、50 个版本、数百条 Review。
- 空计划草稿、无 Tag、无 Segment。
- 只读 Viewer、账号禁用、成员被移除。
- 慢查询、保存中、重复点击、网络失败。
- 已 Revised、Cancelled、Timeout、Archived。
- 时区切换、跨日 Segment、夏令时边界。

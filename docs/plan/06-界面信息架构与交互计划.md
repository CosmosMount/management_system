# 界面信息架构与交互计划

## 1. 导航结构

```text
项目管理
├── 我的工作
├── 全部 Task
├── Tag 管理
├── 人员计划
├── 资源冲突
├── 待我处理
├── 站内通知
└── 管理设置（有权限时）
```

系统没有 Project 入口。默认首页以 Task 和个人时间计划为中心，Tag 只用于筛选。

## 2. 路由规划

| 路由 | 页面 | 替代/新增 |
|---|---|---|
| `/progress` | 我的 Active Milestone、今日 Segment、待确认、通知 | 重做 |
| `/progress/tasks` | Task 列表、筛选、保存视图 | 新入口 |
| `/progress/tasks/new` | 创建 Task 与初始计划 | 新入口 |
| `/progress/tasks/[id]` | Task 工作台 | 新入口 |
| `/progress/tags` | Tag 管理与关联 Task | 新增 |
| `/progress/resources` | 人员计划与实际时间轴 | 新增 |
| `/progress/resources/conflicts` | 冲突中心 | 新增 |
| `/progress/approvals` | Milestone Review 与 Revision | 重做 |
| `/progress/notifications` | 站内通知中心 | 新增 |
| `/admin/project-management` | 角色、策略、通知、冲突规则 | 新增/重做 |

当前已上线 `/progress`、`/progress/tasks`、`/progress/tasks/[id]`、`/progress/resources`、`/progress/resources/conflicts` 和 `/progress/notifications`。旧 `/progress/task/:id` 重定向到 `/progress/tasks/:id`，旧 `/progress/projects/*` 和 `/progress/kanban` 回到 `/progress`，但仍不解析旧 Project/Task 标识；未上线的旧阶段、周报、风险或提醒地址没有业务页面。

## 3. 首页“我的工作”

首屏回答：

- 我当前负责哪些 Active Milestone。
- 今天和未来 7 天有哪些 Planned Segment。
- 哪些 Planned Segment 等待确认。
- 哪些 Milestone 临期/逾期。
- 我有哪些待 Review / 待 Revision 审批。
- 我有哪些未读站内通知和资源冲突。

卡片必须可直达对象，不把所有操作堆在首页。空状态要说明下一步，例如“当前没有计划工作，可创建 Planned Segment”。

## 4. Task 列表

### 4.1 筛选

- 状态、优先级。
- 是否独立 Task。
- Tag。
- 我参与的角色。
- Active Milestone 负责人。
- Milestone 到期范围、是否逾期。
- 是否有待确认 Revision/Review/Conflict。
- 组织范围（team/techGroup）。
- 归档/逻辑删除历史仅有权用户可见。

筛选写入 URL，刷新可复现。大列表使用服务端分页，不一次加载全部 Node/Segment。

### 4.2 列表字段

- Task 名称与状态。
- Tag。
- 当前 Active Milestone。
- 当前里程碑预期完成时间/逾期。
- Task Owner。
- 当前计划版本号。
- 最近一次业务变更时间。
- 风险/冲突/待审批徽标。

## 5. 创建 Task

采用三步向导：

1. 基本信息：名称、描述、组织范围、Tag、优先级、成员、Revision 策略。
2. 初始计划：按顺序编辑 Milestone，并设置末尾 Termination。
3. 检查与创建：展示线性链、总时间范围、权限和人员计划提示。

创建后默认保存为 Draft。用户显式“激活 Task”后首个 Milestone Active。

编辑器要求：

- 拖拽排序同时支持键盘上移/下移。
- 每个 Milestone 可折叠。
- 完成条件和验收要求分开。
- 时间顺序异常立即显示。
- Termination 固定在末尾，不能拖到中间。
- 保存前服务端再次验证。

## 6. Task 工作台

### 6.1 标签页

| 标签 | 内容 |
|---|---|
| 概览 | Task 元数据、成员、当前状态、当前 Milestone、快捷动作 |
| 当前计划 | Current Plan 时间线和 Node 详情 |
| 修订与历史 | Revision、历史版本、版本比较 |
| 验收 | 当前/历史 Milestone Review |
| 人员投入 | 关联 Planned/Actual Segment 与计划实际对比 |
| 审计 | 关键业务事件 |

### 6.2 当前计划时间线

视觉语义：

- Current：实线、高对比。
- Historical：弱色、虚线、默认折叠。
- Milestone：目标节点。
- Revision：橙色版本切换节点。
- Termination：明确终点样式。
- Active：主色描边和“当前”标识。
- Completed：成功标识但保留原计划时间。
- Revised：弱化并指向替代版本。

时间线不能只靠颜色表达状态，必须同时显示图标和文字。

## 7. Revision 编辑与比较

### 7.1 编辑器

进入 Revision 时固定展示：

- 修订原因。
- 基线版本号。
- 修订起始节点。
- 受影响 Milestone 数量。
- 受影响 Planned Segment 数量。

用户在候选计划中新增、删除、调整 Node。Completed 前缀锁定只读。

### 7.2 版本比较

比较视图按三层显示：

1. 结构：新增、删除、移动 Node。
2. 字段：目标、条件、时间、验收要求变化。
3. 资源：关联 Planned Segment 是否需要重新确认。

移动与“删除后新建”必须区分。每项差异显示旧值、新值和 Revision 原因。

### 7.3 并发冲突

若基线已不是 Current：

- 不自动覆盖。
- 显示“当前版本 vN，你的草稿基于 vM”。
- 提供查看新差异、复制草稿内容到新 Revision 的受控操作。
- 用户确认前不写任何 Current Plan。

## 8. Milestone Review

当前 Milestone 面板分：

- 目标/条件/截止。
- 提交证据。
- 历史 Review 时间线。
- Reviewer 操作。

Approved、Rejected、Revision Required 使用独立按钮和确认对话框。Rejected/Revision Required 的说明必填。审批前展示 Task 名称、当前版本和 Milestone，避免用户在错误上下文操作。

## 9. Work Segment 交互

### 9.1 人员时间轴

- 行：Person。
- 横轴：时间。
- Planned：空心/浅色/虚线。
- Actual：实心。
- 冲突：边缘警示和冲突徽标。
- Revised Node 关联：待确认图标。

时间轴支持：

- 7/14/30 天范围。
- 人员、Task、Tag、Role、Priority 筛选。
- 拖拽调整 Planned Segment。
- 框选后批量创建。
- 多选后批量移动/取消/确认。
- 点击打开侧边详情，不跳失当前时间范围。

### 9.2 计划确认

Planned 到期后，成员可：

- 一键“与计划一致”生成 Actual。
- 修改实际时间/Allocation/产出后确认。
- 部分确认并保留剩余 Planned。
- 标记未执行并填写原因。

默认表单只显示必要字段，高级字段折叠，符合低记录负担原则。

## 10. Resource Conflict

Conflict 在两个位置显示：

- 人员时间轴：发生位置标记。
- Task 人员投入：关联 Task 上下文标记。

冲突详情必须解释：

- 时间范围。
- 涉及 Segment。
- Allocation 总和。
- Role、Priority、Task。
- 触发规则。
- 可选建议。

操作只有“确认已知、调整 Segment、解决、忽略至某日”。建议不自动执行。

## 11. 站内通知

顶部铃铛显示未读数，通知中心支持：

- 未读/全部。
- 类型筛选。
- 标记已读/全部已读。
- 跳转业务对象。
- 事件级飞书偏好设置入口。

站内通知不会因为用户关闭飞书而消失。已删除或无权对象的链接显示“对象不可用”，不泄露名称或详情。

## 12. Tag 界面

- 展示 Tag 名称、颜色、说明和关联 Task 数量。
- 删除 Tag 明确提示“只移除分类，不删除 Task”。
- Task 详情可随时添加、替换或移除多个 Tag。
- 不展示 `legacy-import` 或其他旧来源标记；所有 Tag 都由新系统创建并遵循同一行为。

## 13. 响应式与无障碍

### 13.1 桌面

- 1440x1000 为主验证尺寸。
- 时间轴可横向滚动，但页面本身不得意外横向溢出。
- 大型比较视图允许固定双栏，最小列宽明确。

### 13.2 移动

- Pixel 5 作为自动化基线。
- 时间线改为垂直卡片。
- 版本比较改为逐项“旧/新”堆叠。
- 资源时间轴改为按人员的日列表，不强行缩小桌面甘特图。
- 批量拖拽在移动端提供表单式日期调整。

### 13.3 无障碍

- 所有拖拽都有键盘等价操作。
- 图标有可读名称。
- 状态不只靠颜色。
- 对话框焦点锁定，关闭后返回触发控件。
- 表单错误关联字段并聚焦首个错误。
- 时间和百分比提供屏幕阅读器文本。

## 14. 极端状态检查

每个页面必须检查：

- 超长 Task/Milestone/人员/Tag 名称。
- 200 个 Node、50 个版本、数百条 Review。
- 空计划草稿、无 Tag、无 Segment。
- 只读 Viewer、账号禁用、成员被移除。
- 慢查询、保存中、重复点击、网络失败。
- 已 Revised、Cancelled、Timeout、Archived。
- 时区切换、跨日 Segment、夏令时边界。

# 服务端操作与接口计划

## 1. 接口形式

继续使用 Server Actions 作为浏览器写入口。外部系统只需要飞书登录/回调和通知投递，不为内部 UI 额外创建 REST API。

规则：

- action 接收 `unknown` 或明确 DTO，第一步 Zod parse。
- action 只做认证、授权上下文、调用 application service、结果映射和 revalidate。
- Prisma 多表事务只存在于 application service。
- 查询通过 server component/query facade，不把 Prisma 模型直接传给 client。
- 所有错误返回稳定 code 和中文消息。

## 2. Tag 操作

| Action | 权限 | 事务/审计 | 备注 |
|---|---|---|---|
| `createTag` | 已登录成员或按团队策略限制 | Tag + audit | 只创建分类 |
| `updateTag` | Tag 创建人/Admin | 乐观锁 + audit | 不触碰 Task 状态 |
| `archiveTag` | Tag 创建人/Admin | archivedAt + audit | 关系保留但默认不再可选 |
| `deleteTag` | Admin + 二次确认 | 删除 TaskTag/SegmentTag + audit | 不删除 Task/Segment |
| `setTaskTags` | Task Editor | 差异更新 TaskTag + audit | 任意数量 Tag |

## 3. Task 与计划操作

| Action | 前置条件 | 幂等/并发 | 结果 |
|---|---|---|---|
| `createTaskDraft` | 可创建 Task | client idempotencyKey | Task + 成员 + Draft Version + Nodes |
| `activateTask` | Task Draft、计划合法、Task Owner | task lockVersion | Version Current、首 Milestone Active |
| `updateTaskMetadata` | 非 Archived、Task Editor | expectedLockVersion | 只改非计划语义字段 |
| `archiveTask` | 已结束 | expectedLockVersion | status Archived |
| `createRelatedTask` | 可查看原 Task 且可创建 | idempotencyKey | 新 Task 关联原 Task |
| `deleteTaskDraft` | 从未激活 Draft | 二次确认 | 逻辑删除 + audit |

创建计划 DTO：

- Task title/description/priority。
- tags。
- Task members 与 revisionApprovalMode。
- 有序 Milestone 列表。
- 每个 Milestone 的 goal、criteria、expectedCompletedAt、reviewRequirements、人员。
- 最后 Termination 的计划条件与预计时间。

服务端必须重新排序并验证，不信任客户端 sequence。

## 4. Revision 操作

| Action | 权限 | 关键校验 | 通知 |
|---|---|---|---|
| `createRevisionDraft` | Task Editor | Task Active、基于 Current Version | 发起人站内确认 |
| `updateRevisionDraft` | 草稿创建人/Task Owner | Draft、expectedUpdatedAt | 无 |
| `previewRevisionDiff` | Task Viewer | 只读 | 无 |
| `submitRevision` | Task Editor | 草稿计划合法 | Reviewer 站内 + 飞书 |
| `approveRevision` | Task Reviewer/Admin | 不得自审（策略可配置） | 发起人和受影响成员 |
| `rejectRevision` | Reviewer | 必填意见 | 发起人 |
| `applyRevision` | DIRECT owner 或 approve 流程 | 锁 Task、基线仍 Current | 原子切版本 + 广播 |
| `cancelRevision` | 发起人/Owner | 未生效 | 仅站内 |

`applyRevision` 内部步骤：

1. `SELECT ... FOR UPDATE` 锁 Task。
2. 校验 `basePlanVersionId == task.currentPlanVersionId`。
3. 校验已 Completed 节点内容和顺序前缀未变。
4. 写新 Node 和 `PlanVersionNode`。
5. 旧 Current -> Historical。
6. 候选 Version -> Current。
7. 旧 Active Milestone -> Revised。
8. 计算新 Active Milestone 或 Termination。
9. Task.lockVersion + 1。
10. 标记受影响 Planned Segment 待确认。
11. 写 Audit、InAppNotification、Outbox。

## 5. Milestone Review 操作

| Action | 允许人 | 关键校验 |
|---|---|---|
| `submitMilestoneForReview` | Milestone Owner/Member | Current + Active，证据满足要求 |
| `approveMilestone` | Task Reviewer/Admin | 最新 Pending、不得重复、检查清单完整 |
| `rejectMilestone` | Reviewer/Admin | 必填说明 |
| `requireMilestoneRevision` | Reviewer/Admin | 必填原因 |
| `revokeReview` | 受限管理员 | 未推进事实可普通撤销；已推进走纠错流程 |
| `listMilestoneReviews` | Task Viewer | 游标分页 |

所有 Review action 使用 `idempotencyKey`，服务端不允许相同请求重复推进。

## 6. Termination 操作

| Action | 权限 | 规则 |
|---|---|---|
| `confirmTerminationSuccess` | Task Owner/Reviewer | 所有前置 Milestone Completed |
| `confirmTerminationFailure` | Task Owner/Reviewer | 必填原因与总结 |
| `confirmTerminationCancellation` | Task Owner/Admin | 必填取消原因 |
| `confirmTerminationTimeout` | Task Owner/Reviewer | 必填超时依据，不由 cron 自动调用 |

结束时取消未完成 Node，保留历史，更新 Task 状态并通知所有 Task 成员。

## 7. Work Segment 操作

| Action | 权限 | 原子性/限制 |
|---|---|---|
| `createWorkSegment` | 本人或 Resource Manager | 单条 |
| `batchCreatePlannedSegments` | Resource Manager | 最大 100 条，全成全败 |
| `updateWorkSegment` | 本人或 Manager | expectedUpdatedAt |
| `movePlannedSegments` | 同上 | 每项版本，全成全败 |
| `splitPlannedSegment` | 同上 | 子段覆盖原范围且不重叠 |
| `mergePlannedSegments` | 同上 | 同人同语义，来源均保留 |
| `cancelPlannedSegment` | 同上 | 必填原因 |
| `confirmPlannedSegment` | 本人或 Manager | 生成 Actual + 来源 |
| `partiallyConfirmSegment` | 本人或 Manager | 覆盖范围不能超原计划 |
| `createActualSegment` | 本人或 Manager | 可无计划来源 |
| `relinkPlannedSegment` | 本人或 Manager | Node Revised 后人工重关联 |
| `softDeleteActualSegment` | 本人或 Manager | 必填原因，逻辑删除 |

批量操作失败时返回具体行号和错误 code，但不部分提交。超过 100 条要求拆批。

## 8. Resource Conflict 操作

- `scanConflictsForPerson(personId, range)`：worker/internal。
- `listResourceConflicts(filters, cursor)`：Resource Viewer。
- `acknowledgeConflict(conflictId)`：涉及人员或 Manager。
- `resolveConflict(conflictId, resolutionNote, changedSegmentIds)`：Manager。
- `ignoreConflict(conflictId, reason, ignoredUntil)`：Manager。
- `previewConflictSuggestion(conflictId)`：只生成建议，不写 Segment。
- `applyConflictSuggestion(conflictId, proposal, expectedVersions)`：明确确认后调用现有 Segment 更新服务。

## 9. 站内通知操作

- `listNotifications(cursor, unreadOnly)`
- `markNotificationRead(id)`
- `markAllNotificationsRead(before)`
- `getNotificationPreferences()`
- `updateNotificationPreferences(input)`

站内通知记录在业务事务内创建。飞书偏好关闭只阻止非强制飞书投递，不删除站内记录。

## 10. 授权动作枚举

采用稳定 action 字符串：

```text
tag.create
tag.update
tag.delete
task.create
task.view
task.update_metadata
task.manage_members
task.activate
task.archive
plan.view_history
revision.create
revision.review
revision.apply
milestone.submit_review
milestone.review
task.terminate
segment.view
segment.manage_self
segment.manage_others
conflict.view
conflict.resolve
audit.view
```

授权策略只接受这些枚举，禁止页面自行组合角色条件。

## 11. 输入与输出版本

- Audit payload 带 `schemaVersion`。
- 飞书/站内通知 payload 带 `payloadVersion`。
- 数据导出和审计快照带明确 `schemaVersion`。
- Server Action DTO 在内部代码发布中同步升级，不维持旧客户端长期兼容。
- 用户打开旧页面后提交过期表单，应返回刷新提示，不做隐式降级。

## 12. 旧操作边界

旧 Project、Stage、Task、submission、DDL、weekly、risk 和 reminder action 已在重构前删除。实施期间不提供兼容 wrapper；只新增本计划定义的 Task、Plan、Review、Segment 和 Conflict action。

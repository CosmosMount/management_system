# docs/AGENTS.md

本文件仅补充 `docs/` 目录的文档约定；全仓开发、安全、验证和审查规则继承根目录 [AGENTS.md](../AGENTS.md)，不在这里重复定义。

## 文档职责

- [TECH.md](TECH.md)：架构、数据模型、基础设施与配置说明。
- [TESTING.md](TESTING.md)：测试入口、安全环境、验证分层和业务验收场景。
- [NOTIFICATIONS.md](NOTIFICATIONS.md)：通知事件、收件人、机器人路由和投递重试。
- 面向用户的安装、部署和工作流说明写在根目录 [README.md](../README.md)。
- 环境变量示例维护在根目录 [.env.example](../.env.example)，不得包含真实凭据。

## 编辑原则

- 优先使用中文，表达简洁，保留必要背景；不重复抄写全仓规则或其他文档的完整流程。
- 按本次行为变化更新对应文档，不机械修改所有参考文档；确有独立主题时允许新增文档，不设置过时的文件白名单。
- 先核对实现、配置和现有测试，再描述行为。发现文档与实现不一致时说明并解决，不臆造 API、参数、环境变量或测试结果。
- 保留已有业务说明和他人未提交改动；不为精简篇幅删除仍适用的安全要求、验收场景或操作限制。
- 使用可解析的相对链接，核对文件名、命令及其执行前提；不要在文档中写真实账号、令牌、数据库凭据或其他敏感数据。
- 测试与迁移命令必须写明适用范围和隔离要求；区分本地开发初始化、自动化测试与生产发布操作。

## 验证与审查

- 验证门槛以根目录规则为准；测试操作细节见 [TESTING.md](TESTING.md)，不得用子目录约定降低全仓安全要求。
- 纯文档任务做本次差异的 `git diff --check`、受影响链接/命令核对和内容一致性自查，不默认启动应用、数据库或浏览器。
- 安全规则、测试门槛或审查政策的文档变更仍需独立审查；纯文字调整通常只需自查。
- 文档与代码一起修改时，按整个任务的实际影响选择验证范围，不能以“最后只改文档”为由降低代码门槛。
- 交付时简要说明修改的文档、核对方式、实际验证结果和未解决限制；不把文档核对说成应用测试通过。
